## Behaviour is generic, not `uid`-specific

The observation that `foo` and `properties` disappear identically to `uid` rules out any `uid`-specific code path. The behaviour is the standard Go `encoding/json` default applied uniformly to every unknown top-level key. This matters for the issue's framing: there is no `uid`-specific defect to fix; whatever fix is applied (if any) would be a generic decoder posture decision (strict / permissive / partial-strict), not a `uid` patch.
