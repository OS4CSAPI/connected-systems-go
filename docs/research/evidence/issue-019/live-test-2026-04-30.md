Confirms that the string-form parse-failure path IS strict — the defect is
exclusively in the type-assertion-failure path (numeric / boolean / array /
object inputs).

## Notes

The "defaulted to resultTime" behaviour comes from
`internal/repository/observation_repository.go:22-25`:

```go
if observation.PhenomenonTime == nil {
    t := observation.ResultTime
    observation.PhenomenonTime = &t
}
```

This is what makes the silent drop *worse* than a nil-leaving silent drop:
the GET response is plausibly correct (timestamps present), so the client
has no way to detect the data loss without comparing the original input
verbatim.
