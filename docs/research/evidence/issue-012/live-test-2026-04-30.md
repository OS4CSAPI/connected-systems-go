## T5 — Probe `?id=` filter on /datastreams (adjacent finding)

This was triggered by the static finding that `datastream_repository.go:164` references a `unique_identifier` column that the model no longer declares.

```
GET /datastreams?id=foo                       → HTTP 500 {"error":"Internal server error"}
GET /datastreams?id=urn:test:ds:something     → HTTP 500 {"error":"Internal server error"}
GET /datastreams?id=4300e090-7893-4c01-...    → HTTP 500 {"error":"Internal server error"}
```

All three return 500 unconditionally. This confirms the dangling SQL column reference is a real, currently-active defect on HEAD — but it is **not** the defect issue #12 describes. It is collateral damage from the partial cleanup in commit `1562201`. Recommend filing as a separate issue.
