## Test matrix

All requests are
`POST /datastreams/9d3459e8.../observations` with the body shown.

| # | Body (`result`) | Spec expectation | Actual | Verdict |
|---|---|---|---|---|
| T1 | `{"baro_altitude": "NaN"}` | 201 (matches declared nilValue) | **400** `"result.baro_altitude must be a number"` | bug confirmed |
| T2 | `{"baro_altitude": "-Infinity"}` | 201 (matches declared nilValue) | **400** same message | bug confirmed |
| T3 | `{"baro_altitude": 42.5}` (control) | 201 | 201 | control passes |
| T4 | `{"baro_altitude": "banana"}` (control — undeclared string) | 400 | 400 same message | control passes |

## Critical observation — T1 vs. T4 produce identical errors

The validator does **not differentiate** between a declared-nilValue string
and an arbitrary string. Both T1 (`"NaN"`, declared) and T4 (`"banana"`,
undeclared) get the identical error message
`"result.baro_altitude must be a number"`. This is the proof that the
validator never consults `component.NilValues` — if it did, T1 would
return 201 (or at minimum produce a different error message).
