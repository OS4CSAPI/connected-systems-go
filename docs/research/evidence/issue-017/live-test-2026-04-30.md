# Issue #17 — Live test (HEAD `0255a10`)

Date: 2026-04-30. Server: `https://129-80-248-53.sslip.io/csapi-go-head`.

## Behavioural map for DELETE error classes

### T1 — DELETE non-existent datastream (no preflight)

```
DELETE /datastreams/00000000-0000-0000-0000-000000000000
HTTP/1.1 204 No Content
```

**Issue body predicted 500. Actual: 204.** GORM's `db.Delete` returns nil for
0-row matches, the handler treats nil as success, response is 204.

### T2 — DELETE non-existent system (no preflight)

```
DELETE /systems/00000000-0000-0000-0000-000000000000
HTTP/1.1 204 No Content
```

Same: 204, not 500.

### T3 — DELETE non-existent procedure (no preflight)

```
DELETE /procedures/00000000-0000-0000-0000-000000000000
HTTP/1.1 204 No Content
```

Same: 204, not 500.

### T4 — DELETE non-existent observation (preflight present)

```
DELETE /observations/00000000-0000-0000-0000-000000000000
HTTP/1.1 404 Not Found
{"error":"Observation not found"}
```

Pre-flight `GetByID` correctly produces 404 here.

### T5 — DELETE non-existent command (preflight present)

```
DELETE /commands/00000000-0000-0000-0000-000000000000
HTTP/1.1 404 Not Found
{"error":"Command not found"}
```

Same: 404.

### T6 — DELETE FK-conflicting datastream (real error)

Reusing the pair created during #16 reproduction (still exists because cascade
is broken):

```
DELETE /datastreams/2c28b903-ab1d-45a9-9dd1-9718b0ddf30d
HTTP/1.1 500 Internal Server Error
{"error":"Failed to delete datastream"}
```

This is the case the issue body's `classifyRepoError` would map to **409
Conflict** — currently returns 500 with opaque body.

### T7 — DELETE with malformed UUID

```
DELETE /datastreams/not-a-uuid
HTTP/1.1 204 No Content
```

**Surprising result**: a malformed UUID against a `uuid`-typed column should
produce SQLSTATE `22P02`, but the response is 204. The classification gap is
even worse than the issue body documents — a client cannot distinguish
"deleted", "never existed", or "input was structurally invalid".

## Summary table

| Test | Predicted by issue body | Actual |
|---|---|---|
| Missing ID, no-preflight handler | 500 | **204** |
| Missing ID, preflight handler | 500 | 404 (correct) |
| FK conflict | 500 | 500 (issue's primary target — correct) |
| Malformed UUID | (not addressed) | 204 (additional gap) |

The issue's central thesis (no error-class discrimination → opaque 500s for
recoverable conflicts) holds. The framing of the status quo as "everything →
500" is inaccurate — the actual pattern is more "everything that fails → 500;
everything that should-fail-but-doesn't → 204".
