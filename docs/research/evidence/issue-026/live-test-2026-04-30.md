## Test matrix on `/systems`

| Query | Result count (out of 17 baseline) |
|---|---|
| `?limit=100` (baseline) | **17** |
| `?uid=urn:test:issue1:sys:1&limit=100` | **17** (unknown param ignored) |
| `?id=urn:test:issue1:sys:1&limit=100` | **1** (URL-form filter works) |

## PowerShell run (verbatim)

```pwsh
$base='https://129-80-248-53.sslip.io/csapi-go-head/systems'
$uid='urn:test:issue1:sys:1'
$enc=[uri]::EscapeDataString($uid)
"total=$( (Invoke-RestMethod ($base+'?limit=100')).features.Count )"
"uid=$( (Invoke-RestMethod ($base+'?uid='+$enc+'&limit=100')).features.Count )"
"id-urn=$( (Invoke-RestMethod ($base+'?id='+$enc+'&limit=100')).features.Count )"
"id-local=$( (Invoke-RestMethod ($base+'?id=666ed3fe-bccf-4670-bb85-a0a3c4562772&limit=100')).features.Count )"
"foo=$( (Invoke-RestMethod ($base+'?foo=bar&limit=100')).features.Count )"
```

Output:

```
total=17
uid=17
id-urn=1
id-local=1
foo=17
```

## Findings

- `?uid=` and `?foo=bar` are observationally equivalent — both pass
  through `url.Values.Get("id")` returning empty, no filter applied.
- `?id=` accepts both URI form and local-UUID form, returning a single
  matching system in each case → confirms the dual-semantics SQL filter
  is wired and exercised end-to-end.
- The system used (`urn:test:issue1:sys:1`, local
  `666ed3fe-bccf-4670-bb85-a0a3c4562772`) was created by issue-1 testing
  earlier in this evaluation series and persists per #16 retention.
- No errors, no warnings — the silent no-op behaviour for `?uid=` is
  exactly the publisher-facing UX problem the body describes.
