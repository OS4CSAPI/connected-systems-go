==============================================================================
DIAGNOSIS
==============================================================================

  Spec-correct property name: documents       → DROPPED
  cs-go's struct-tag spelling: documentation  → PRESERVED

Underlying types, JSONB persistence, marshal/unmarshal pipeline, and
output emission all work correctly. The bug is exactly: the json tag
literal in the Go struct does not match the spec property name. Any
client that conforms to the SensorML JSON encoding spec will lose its
`documents` data without warning.

The HTTP 201 returned for the spec-correct POST is misleading: the server
indicates success while having silently discarded part of the payload.
Silent partial-data loss with a 2xx status is the worst-class flavor of
this kind of bug because clients have no signal to retry, log, or alert.
