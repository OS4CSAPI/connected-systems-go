==============================================================================
2. WHY DATA IS SILENTLY DROPPED
==============================================================================

Go's encoding/json default behavior:
  - On Unmarshal: unknown fields are silently ignored (no error returned
    unless DisallowUnknownFields() is explicitly enabled — cs-go does not
    enable it).
  - On Marshal: a field with the omitempty tag and zero value is omitted.

Concrete sequence for the issue's reproducer:
  (a) Client POSTs SML with property name "documents" (spec-correct).
  (b) The Go SystemSML struct has tag `json:"documentation,omitempty"` —
      not `json:"documents,..."`. The "documents" array is unknown to the
      unmarshaller and silently skipped. Documentation field stays nil.
  (c) System persists to DB with empty/null documents JSONB column.
  (d) Later GET serializes Documentation; nil + omitempty → field absent
      from output entirely.

The defect is not a serializer bug, an output-encoding bug, or a partial
mapping bug. It is a single-character class of bug — every "Documentation"
struct field's json tag is the wrong literal string.

==============================================================================
3. WHY THE CONTROL TEST WORKS
==============================================================================

If a client sends `documentation` (cs-go's tag spelling, not the spec's
property name), step (b) above succeeds: the field unmarshals, persists,
and round-trips. This proves the underlying types, persistence, and
serialization paths are all functional. The defect is isolated entirely
to the json struct-tag literal.
