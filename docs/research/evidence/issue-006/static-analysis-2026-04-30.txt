   PATTERN: @link is used for parent/hierarchical/cross-collection refs that may carry
   metadata (rel, type, title, uid, hreflang, rt, if). @id is used for the immediate
   parent of a sub-resource where the parent collection is fixed by context
   (Observation always belongs to a Datastream; Command always belongs to a ControlStream).

   IMPORTANT: there is NO `system@id` field defined for Datastream or ControlStream
   in OGC 23-002. The flat `system@id` shape used by OSH SensorHub at the datastream
   level is non-conformant with this spec.

6. Open spec questions
   --------------------
   Q4 (issue): href format — relative path vs absolute URL?
   Spec line 318-322:
       href:
         description: URL of target resource
         type: string
         format: uri
         examples:
           - https://data.example.com/link/to/resource
   `format: uri` (RFC 3986) typically connotes absolute URI. cs-go emits
   `"systems/<uuid>"` (relative-reference). RFC 3986 §5 defines reference
   resolution rules using a base URI; clients can resolve. Strict OAS validators
   may flag relative as a `format: uri` violation. This is a minor conformance
   gap, candidate for a P3 follow-up.

   Q3 (issue): emit BOTH @id and @link on Datastream/ControlStream?
   Spec defines only `@link` for these resources — adding `system@id` would be
   a non-spec extension property. Recommendation: do NOT. Client-side parsers
   should be updated to read `@link.href` (already done in ogc-client-CSAPI_2 #166).
