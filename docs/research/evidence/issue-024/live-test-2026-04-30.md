## Summary

The body's symptom is reproducible:

1. Server-synthesised inline `@link.href` is **relative** (consistent
   with the static-analysis trace pointing to handler line `:136` /
   `:145` which builds `"systems/" + ID`).
2. The supplementary `links[]` array on the same response is
   **absolute** — internal inconsistency confirmed.
3. User-supplied absolute hrefs round-trip correctly, so the fix can be
   applied with no breakage to existing well-behaved clients.

The one observation worth recording: the fix's *outermost* site can be
the formatter (cheaper, makes response correct) or the handler
(normalises storage). Recommended approach: apply the helper at **both**
sites for defence in depth (the helper is idempotent so this is safe).
